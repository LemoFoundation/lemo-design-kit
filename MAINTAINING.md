# Maintaining this kit

Notes for whoever owns the kit. Everyone else wants [README.md](README.md).

## Where this came from

Ported out of the personal `VideoProjects` repo, where the same capability runs as the
`graphic-design` skill under Claude Code. That version resolves a brand pack from the filesystem
(`_tools/brands/lemo-encore/`) and layers it over a universal `STYLE.md`. **This kit is
self-contained instead** — `references/brand.md` is the universal discipline and the lemo-encore
pack flattened into one file, because a claude.ai session has no filesystem.

Deliberately left behind: the carousel format layer, the travel-diary recipe, the Python helpers,
the PowerShell fallback runner, and the brand-pack resolution mechanism. None survive the move to a
web session, and none are needed here.

## Shipping a change

Everything is one cross-platform Python script — **macOS, Linux and Windows alike**. Packaging
needs only the standard library; regenerating logo artwork additionally needs Pillow
(`pip install pillow`), and only whoever edits the masters ever runs that.

1. Edit under `skill/lemo-encore-design/`.
2. Build:
   ```
   python build.py              # package build/lemo-encore-design.zip, then self-check
   python build.py --assets     # ALSO regenerate logo artwork from the masters first
   python build.py --check      # verify an existing zip without rebuilding
   ```
   You only need `--assets` if you changed something in `assets/logos/`.
3. Commit the source change. `build/` is gitignored.
4. Cut a GitHub release and attach `lemo-encore-design.zip`. **That is the only release asset** —
   the logos travel inside it.
5. Tell the team to re-download. **There is no push mechanism** — whoever uploaded v1 keeps running
   v1 forever until they upload a new one.

**The zip must use forward slashes** in its entry paths, with the `lemo-encore-design/` folder and
`SKILL.md` at its root. The ZIP spec (4.4.17.1) requires forward slashes, and a spec-compliant
extractor reads a backslash entry as one flat filename rather than a folder, so the skill silently
fails to load. Python's `zipfile` always normalises to forward slashes, so this is structurally
impossible now — but **don't reach for PowerShell's `Compress-Archive`**, which gets it wrong on
Windows PowerShell 5.1. That bug is why an earlier `build.ps1` existed; it's gone, and the build is
OS-agnostic because most of the team is on macOS. `python build.py --check` asserts all of this.

## Brand assets

There are two copies of the logo artwork and they serve different jobs:

- **`assets/logos/`** — the 5000px masters. Source of truth. Never referenced at runtime.
- **`skill/lemo-encore-design/assets/logos/`** — 1500px copies plus `.b64` sidecars and
  `manifest.json`, generated by `build.py --assets` and bundled in the skill zip. This is what
  Claude actually uploads.

**Do not hand-edit the generated copies** — rerun `python build.py --assets`.

**There is no Penpot template any more.** The kit used to ship a `lemo-brand-assets.zip` that staff
imported from the Penpot dashboard; that step is gone and so is the file. A blank Penpot file is
now the supported starting point, and `SKILL.md` step 3 uploads the artwork itself via
`penpot.uploadMediaData`, creating the groups and shapes with the names below.

Naming is **load-bearing** in three places at once — `build.py`'s `VARIANTS` table,
`SKILL.md` step 3, and `brand.md`'s lookup:

- Groups named exactly `Lemo Logos` and `Encore Logos`
- Children named `Logo / Black`, `Logo / White` (LEMO) and `Logo / Navy`, `Logo / Red`,
  `Logo / White` (Encore)

Rename anything and every build breaks silently for everyone already running the skill.

**Encore White is different artwork from Encore Navy and Red.** Its wordmark is inset a further ~7%
on each side (alpha extent 11.40–92.13% vs 4.07–96.20%). `brand.md` carries a separate row for it
and `manifest.json` measures every variant independently. Don't collapse them back into one
per-sub-brand figure — using the Navy box for the white mark renders it ~9% oversized and
off-centre. If you add a variant, `build.py --assets` measures it for you.

**Size ceiling.** The 1500px copies exist because base64 travels through `execute_code` as literal
tokens. A 5000px master costs ~39k tokens to upload; 1500px costs ~7-10k. `SKILL.md` instructs
uploading only the variants a piece needs. If you raise `LOGO_PX` in `build.py`, you are raising
the per-session cost for everyone — check the token figures it prints before committing.

## Fonts and licensing

Only Montserrat is assumed. It's a Google font, ships with Penpot, and per the brand book is a
genuine brand face for both sub-brands — so the kit works with zero font installation.

**Before putting font binaries in this repo, check what you're allowed to redistribute:**

- Display faces derived from sports-team wordmarks carry trademark considerations separate from
  any font licence; check both before adding one.
- **Futura** — commercial under every cut (Linotype, Paratype, Bitstream). Redistribution is not
  permitted.
- **Pirulen** — a Larabie face; free for personal use, commercial use typically needs a licence.

Safest is to keep `assets/fonts/` as instructions on where to obtain each one, and let people
install them into their own Penpot account. Flagged 2026-08-20; the call is LEMO's.

## Keeping it in sync with VideoProjects

The two copies will drift. When a real lesson gets learned on either side:

- **Brand decisions** (a colour rule, a type gotcha, a logo measurement) → update *both*
  `_tools/brands/lemo-encore/STYLE.md` in VideoProjects and `references/brand.md` here.
- **Penpot API gotchas** → `references/penpot-api.md` in both. Usually copy-paste identical; this
  version just has repo-local paths stripped.
- **Method / workflow changes** → likely diverge. The VideoProjects skill assumes a designer
  driving it; this one assumes a non-designer with nobody reviewing the output. Don't blindly copy
  `SKILL.md` across.

Record brand decisions with a dated line in the changelog of the VideoProjects pack, the way that
repo already does. This kit's `brand.md` intentionally has no changelog, to stay readable for
non-designers.

## Things to watch

- **Plan gating.** Custom connectors need Pro/Max/Team. A free-tier teammate can't use this at all,
  and it looks like "the connector page has no Add button."
- **The tab-open requirement is the #1 support call.** Penpot's MCP is browser-relayed, so Penpot
  must be open with MCP on *before* the chat starts.
- **Everyone needs their own Penpot key.** Never distribute yours — a key is account-scoped.
- **The empty-file problem is handled, but verify it stays handled.** A new account has no logos;
  `SKILL.md` step 3 uploads them. If someone reports "it won't design anything" or sees an
  improvised wordmark in live type, that upload path is broken — check `penpot.uploadMediaData`
  hasn't changed signature and that the `.b64` sidecars are actually inside the shipped zip.

## Demo suggestion

The pitch lands better if they watch a **revision**, not a build. Have a flyer already made, then
let someone ask for three changes live — a wrong date, a bigger headline, a dark version. The point
isn't that Claude can design; it's that they stop waiting on you for round two.
